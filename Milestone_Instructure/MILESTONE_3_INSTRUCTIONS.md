## 2. Run in VS Code (PowerShell)

1. Open folder `E:\semantic-search-engine` in VS Code.
2. Choose **Ctrl+Shift+P → Python: Select Interpreter → `E:\semantic-search-engine\.venv\Scripts\python.exe`**.
3. Keep any model-download terminal separate. Open a new terminal and run these commands from the project root.
4. Verify the dataset and previous lab exist:

```powershell
Test-Path .\data\raw\documents.csv
Test-Path .\labs\lab_5_1_cosine_search.py
.\.venv\Scripts\python.exe scripts\validate_dataset.py
```

Both `Test-Path` commands should print `True`. If not, merge M1 and M2 files first.

### A — Create/update the Chroma database

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --index
```

This loads the exact Milestone 1 corpus and the **same model and vectors** as Lab 5.1, then writes a persistent Chroma collection to `chroma_db/`.

### B — Test semantic search (top 5)

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --query "How can I protect my online account?"
```

### C — Test a category filter

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --query "How can I protect my online account?" --category cybersecurity
```

### D — Test an inclusive date filter

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --query "How do I secure an account?" --date-from 2026-01-01 --date-to 2026-12-31
```

You can combine filters:

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --query "How do I secure an account?" --category cybersecurity --date-from 2026-01-01 --date-to 2026-12-31
```

Dates are stored as an ISO string and an integer `YYYYMMDD`; Chroma's numerical `$gte`/`$lte` comparisons ensure correct inclusive ranges.

### E — Test persistence after a restart

1. Let the indexing command **finish**. Close its terminal, or open a fresh terminal/process in VS Code.
2. Execute:

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --verify-persistence
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --query "network security"
```

The previous count should persist and the query should return hits without re-indexing.

### F — Compare Chroma to Milestone 2 (10 queries)

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --compare
```

This populates `docs/lab_5_2_results.md` with observed top-1 results, top-5 overlap and query timings. **Finish the TODOs afterward** with screenshots or observed examples. The comparison overwrites the initial template.

### G — Run tests

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_lab_5_2.py -q
```

### H — Rerun indexing safely or force a clean build

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --index
.\.venv\Scripts\python.exe -m labs.lab_5_2_chroma_filters --rebuild-index
```

`--index` uses stable IDs and `upsert`, preventing duplicate rows; `--rebuild-index` deletes **this lab's collection only** and recreates it. Neither deletes other collections.

## 5. Dependencies / honest limitations

- Required: `chromadb`, `sentence-transformers`, `numpy`, `pandas`, `pytest`, `scikit-learn` installed through existing `requirements.txt`.
- No Qdrant/FAISS/Docker/server/API key is needed.
- The sample CSV is **demonstration data**, not a real external corpus. The real-corpus task in Milestone 1 and final project's real-corpus requirement stay open.
- For simplicity this lab reuses a local MiniLM model and derives query embeddings externally; it will not trigger Chroma's default embedding model download.
- Comparing two systems is not an exact identity guarantee: Chroma uses approximate indexing and minor floating-point differences can change near-tie order.
- This package is prepared here. **It has not been run on your own Windows installation**. Record your actual measurements and verify all tasks before committing completion checkboxes.
