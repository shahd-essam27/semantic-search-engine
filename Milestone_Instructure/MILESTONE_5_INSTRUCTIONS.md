## 2. Before running: packages and models

Use **Ctrl+Shift+P → Python: Select Interpreter** → `E:\semantic-search-engine\.venv\Scripts\python.exe`.

Your Week 5 dependencies should already be installed. We use `sentence-transformers`, `numpy`, and `pytest`. **No extra pip packages are required.** CPU is a good default.

Your previous download script should cache:

- `sentence-transformers/all-MiniLM-L6-v2` (English-focused)
- `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (multilingual, supports Arabic)

If both downloads already finished, **do not download them again**. If not finished, let the model downloader complete first. Model weights live in the Hugging Face cache by default, not in this ZIP or GitHub.

## 3. Tasks 5.1–5.7

- **5.1 — Select models:** Already selected above. Later document why they differ in language coverage, dimensions, speed, and size.
- **5.2 — Evaluation set:** Open `data/evaluation/model_comparison_queries.csv` (8 English + 8 Arabic). The relevant document IDs reference the **Milestone 1 English demo corpus**. This is a small hand-authored evaluation, not an external benchmark.
- **5.3 — Fair comparison:** The program generates **fresh document embeddings under each model** and embeds its own queries in the same space. No mixing vectors across models or reusing Milestone 2's English vectors for multilingual search.
- **5.4 — Performance:** Measures model load, embedding time, embedding dimensions, query latency, cached weights (where accessible), and process RSS (when `psutil` happens to be available). RSS is not model-only usage; CPU percent is not measured.
- **5.5 — Retrieval quality:** Recall@5 counts labeled relevant documents retrieved among top five, divided by the three labeled relevant documents. Hit@5 checks whether at least one of those was retrieved. Inspect the detailed CSV for model-specific successes/failures.
- **5.6 — Compare:** Read both English and Arabic scores without assuming which model wins. **Arabic queries against an English corpus are cross-language retrieval**, and do not establish Arabic-only retrieval performance.
- **5.7 — Model choice:** Open the generated `docs/model_comparison.md` and replace its `TODO` lines with your conclusion, trade-offs, and two specific failed examples before checking off the task.

### Run the full evaluation

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_4_model_comparison --evaluate
```

It creates/overwrites:

- `docs/model_comparison.md` — measured comparison and TODO interpretation prompts
- `docs/model_comparison_details.csv` — full per-query results for both models

**Warning:** Running `--evaluate` again **overwrites** `docs/model_comparison.md` and your handwritten TODO answers. If you need to re-run, commit or save your notes first. It does not overwrite earlier milestone results.

To run tests without downloading/encoding models:

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_lab_5_4.py -q
```

To compare on CPU explicitly:

```powershell
.\.venv\Scripts\python.exe -m labs.lab_5_4_model_comparison --evaluate --device cpu
```

If you replace Milestone 1 `documents.csv` with a real-world source, the old relevance IDs may no longer exist: recreate labels for your new dataset before comparing. The program intentionally checks that every labeled ID is present.
